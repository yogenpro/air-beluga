# Document layout research and coverage ledger

Layout source review: **2026-11-11**. This date records reference discovery/read checks, not a document issue date, edition, legal effective date, or renewed review of any travel rule. Research used primary publishers through web search and page/PDF metadata. Where a page provides specimen images, they are references for structure; the game does not reproduce their identities, identifiers or security features. Some PDF image retrieval failed; limits are recorded below.

The country atlas is a generated 4 × 3 set of decorative motifs for GB, US, CA, IN, CN, FR, ID, RO, TH, JP, SG and HK. It is not a government specimen or evidence of a particular edition. Names, dates, identifiers and other evidence remain live text. XY/XZ are explicitly fictional training issuers and have no real-world specimen. No real document photographs or personal data are needed for this implementation.

## Access and precision limits

The [CBP Carrier Information Guide PDF](https://www.cbp.gov/sites/default/files/assets/documents/2023-Nov/Carrier%20Information%20Guide%20ENGLISH.pdf) was a research lead but returned HTTP 403. It is **not** counted as inspected visual evidence. The PRADO Japan index timed out/was unavailable. The source list above records alternatives and partial evidence rather than silently claiming complete visual review. The NCDC-hosted referral-form lead returned 404 on direct fetch; it is search metadata only. US State Department and lab/airline references require further image review for exact field positioning. No row licenses an exact facsimile or security-feature reconstruction.

This ledger reviews document families and their physical/digital roles. It does not certify a travel requirement, provider approval, allowed test method, visa entitlement, expiration consequence or answer. Those belong to the separately dated rule-review ledgers and authored evidence paths. Contemporary live pages cannot establish the rules of a historical shift by themselves.

## Legacy cases, edition selection and archives

Existing documents have validity bounds, not a dedicated issue-date/edition field. `validFrom` must not automatically become “date issued,” “resident since,” booklet version or redesign date. Expiry and travel date also do not uniquely identify an edition. Use a restrained family layout and disclose that it is simulated. Do not invent date of birth, nationality, sex, signature, document serials, chip presence, authority, duration of stay or remaining entries to fill decorative space. A holder's country of issue is not proof of nationality, particularly for I-571/I-327.

For a future case requiring a physical/digital or exact-edition distinction, record explicit structured evidence in new content, add an appropriately narrow registry selector and primary specimen reference, and check the travel date against supported issuance/withdrawal history. If that review cannot be completed, keep the family rendering neutral and do not turn missing art knowledge into passenger denial. Obtainable material conflicts still require the authored checks.

Never patch frozen bundles, release hashes, daily boundaries or past answers to retrofit art metadata. Compatible legacy rendering can recognize the existing authored category/status/form evidence without mutating it. When new facts are needed for gameplay, publish a new version. Layout and atlas changes must preserve readable evidence and not disclose hidden documents or the expected decision.

## Coverage gate and integration

Run `node --import tsx scripts/validate-document-art.ts [data-root]`. The optional root is shared with the content validator. Import-safe `validateDocumentArtFromDisk(root?)` first loads source authoring via `loadContentFromDisk`, then validates the archive library and hashes via `validateLibraryFromDisk`. It checks all `cases[].documents[]`, including not-initially-presented documents. Archives are reached through `library.index.releases` and `library.versions[contentVersion]`, not an assumed `.releases` bundle array. Failures identify authoring/archive, case, document, issuer, type and available form/category.

The resolver `getDocumentDesign(document)` is the sole layout coverage authority. Unknown issuers, unsupported country/type pairs and unsupported forms must return `undefined`; a generic rendering fallback must not make coverage succeed. Explicit training designs are supported entries. The gate does not check generated bitmap quality, atlas pixels, legal correctness or exact edition accuracy. `npm run validate:content` also checks that the country atlas exists. Browser acceptance checks the image response, all visual profiles at desktop/mobile widths, overflow and enlarged inspection.

The main content validator calls `validateDocumentArtFromDisk(process.argv[2])`, so coverage is required by `npm run build` and CI. Tests cover real authoring/archive coverage, new-issuer rejection, unsupported country/type rejection and a hidden-document diagnostic. Review the command's actual document/release counts after any future shift; adding a new country/form requires layout and source review before release.
